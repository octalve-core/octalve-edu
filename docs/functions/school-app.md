# School app — Functions (services, libraries, API routes)

The logic behind one school's screens: for each area, the library files under `src/lib/` (services that talk to the database, pure rules, validation) followed by the API routes
under `src/app/api/v1/schools/[code]/` that expose them. Every handler declares who may call it (`roles:` or `permissions:` on `withAuth`, see [`shared.md`](./shared.md)); the **Who**
column says what the guard allows, and `tests/unit/route-role-guard.spec.ts` fails for a handler that declares nothing and is not on its allowlist with a reason. Every school GET route
also declares the support `area` it belongs to, or is on the out-of-reach list of `tests/unit/route-area-guard.spec.ts` (ADR 0017).

## API routes: School root (`/api/v1/schools/[code]/`)

| Method | Route | File | Who | Description |
| --- | --- | --- | --- | --- |
| GET | `/api/v1/schools/[code]` | `schools/[code]/route.ts` | Member of the school (any role); support area `settings`. | The school as the caller sees it: `{ school: { code, name }, role, campusId, campuses }`. `campuses` is every campus of the school for an ADMIN (a support view reads as ADMIN) and only the caller's own otherwise, none when unassigned. The query names the tenant and runs in `tenant.run`. Listed in the role-guard allowlist as readable by any active member. |

## `src/lib/academics/`

The academic structure of a school: sessions and their terms, classes and arms, subjects, assessment schemes and grade scales. The services return refusals as `{ ok: false, reason }` (`AcademicResult`) instead of throwing, run in one `tenant.run` transaction with the `AuditLog` row written in the same transaction, and never delete: rows are archived.

| File | Description |
| --- | --- |
| `assessment.ts` | Assessment schemes: `listSchemes`, `getScheme` (with the canonical snapshot, JSON and SHA-256), `createScheme`, `updateScheme`, `newSchemeVersion`, `archiveScheme`, `lockScheme`, `snapshotOfScheme`. Components plus exam must equal the total; one live scheme per class or for the school default (`SCOPE_TAKEN`); live names unique. Edited in place only while unlocked, otherwise a new version (`supersedesId`, predecessor archived in the same transaction). `lockScheme` and `snapshotOfScheme` have no caller in `src`, only in tests. |
| `classes.ts` | Classes, arms, subjects and offerings: list, create, update and archive for each (`listClassGroups`, `createArm`, `archiveSubject` and the rest), `listOfferings`, `setOfferings`, `groupsVisibleTo`, `cleanCode`. Limits: class name 60, arm name 30 (at most 26 live arms; capacity 1 to 1000), subject name 80, code 1 to 12 letters or digits. A class with live arms (`HAS_ACTIVE_ARMS`) or a subject a live class studies (`SUBJECT_IN_USE`) cannot be archived. `setOfferings` replaces the full list and is the only real delete. |
| `grading.ts` | Grade scales: `listScales`, `getScale`, `getDefaultScale`, `bandFor`, `createScale` (the first live scale becomes the default), `updateScale`, `newScaleVersion` (the successor takes the default flag), `makeDefaultScale`, `archiveScale` (refuses the default: `DEFAULT_CANNOT_ARCHIVE`), `lockScale`. Edited in place only while unlocked, otherwise a new version. `getDefaultScale`, `bandFor` and `lockScale` have no caller in `src`, only in tests; the results service reads the default scale with its own query. |
| `http.ts` | Role lists `READ_ROLES` (ADMIN, CAMPUS_ADMIN, TEACHING_STAFF, NON_TEACHING_STAFF), `WRITE_ROLES` (ADMIN) and `CAMPUS_WRITE_ROLES` (ADMIN, CAMPUS_ADMIN; using it promises a campus check); zod fields (`isoDateField`, `nameField`, `idField`, `markField`, `componentsField`, `bandsField`); `isPlausibleId` (a copy also lives in `lib/members/http.ts`), `notFound`; `writeLimited` (429 `RATE_LIMITED` after 120 changes in 5 minutes per person and school); `academicFailure`, which maps each `AcademicFailure` to a status, a stable `code` and a message (404, 400 `VALIDATION` with field paths, 409 conflicts). |
| `rules.ts` | Pure calendar rules, no database or clock: `isIsoDate`, `periodKindFor` (K12 TERM, HIGHER_ED SEMESTER, VOCATIONAL COHORT), inclusive `rangesOverlap`, `checkSessionDates`, `checkPeriodDates` (a cohort may be open-ended; a period lies inside its session), `findOverlap`, `findPeriodOverlap` (cohorts may overlap), `effectiveStatus` (ACTIVE past `closeAt` reads CLOSED), `CLOSE_DELAY_MS` (24 h), `FORCE_CLOSE_DELAY_MS` (1 min), `cleanReason` (5 to 300 characters), `currentSessionFor` (a campus's own ACTIVE session, else the school-wide one; only `lib/people/students.ts` uses it), `nextSessionLabel`, `addYears`, `cleanName`. |
| `scoring.ts` | Pure mark and grade rules (ADR 0005): `toHundredths` (a finite number with at most two decimals as integer hundredths, else null), `checkScheme` (1 to 10 components, names 1 to 40 characters unique ignoring case, components plus exam equal the total exactly), `snapshotScheme` (canonical JSON and SHA-256), `checkBands` (half-open `[min, max)` bands covering 0 to 100, no gap or overlap, at most 12, letter 1 to 4, remark 1 to 40) and `gradeFor`, the only way a score becomes a band (null outside 0 to 100 or when the value has more than two decimals). |
| `sessions.ts` | Sessions and terms: `listSessions`, `getSession`, `createSession`, `updateSession`, `activateSession`, `closeSession`, `cancelClose`, `reopenSession`, `archiveSession`, `copyForward` (real or `dryRun`) and the term functions (`listPeriods`, `createPeriod`, `updatePeriod`, `setCurrentPeriod`, `archivePeriod`), plus `settleDueClosings`, `findVisible`, `visibleTo`, `auditAcademic`, `refuse`, `refuseAndRollBack`, `rollingBack` (ADR 0002). Per-scope advisory locks; session label up to 40, term label 60, at most 12 live terms. Closing is scheduled (ADR 0008) and every session read first settles due closings, so a GET can write an audit row. |

## API routes: Academics (`/api/v1/schools/[code]/academics/`)

Sessions and terms, classes and arms, subjects, assessment schemes, grade scales, results and the roll call of a class arm. Every route is `withAuth(..., { tenant: true })`; GET routes declare a support-view `area`, writes declare none. Writes outside attendance and results go through `writeLimited` (120 changes per 5 minutes per person and school, 429 `RATE_LIMITED`, checked before the campus check), and updates and archives answer `changed: false` when nothing needed changing. List routes marked "paged" take `page` and `limit` (default 25, maximum 100). Rows are sorted by file path.
