# Platform console — Functions (libraries, API routes)

The platform administrator's side: the guard (`platformGuard`), the service behind the console, and the routes under `src/app/api/v1/platform/`. These routes are not scoped to a school.

## `src/lib/platform/`

The platform administrator's surface (ADR 0016): who may use it, the field rules and the service over the database's `platform_*` functions.

| File | Description |
| --- | --- |
| `guard.ts` | `platformGuard(auth)` and `platformStepUp(auth, password)`. The guard reads `User.isPlatformAdmin` from the database on every request, never from the session: not an administrator is 403 `FORBIDDEN`, one without active two-step verification is 403 `MFA_REQUIRED`; it returns `null` to go on or the refusal. `platformStepUp` makes the administrator re-type their own password (`proveOwnPassword`: 5 failures per 5 minutes, a success refunded). A school's own ADMIN is refused like anyone else. |
| `http.ts` | The shared field rules and refusals of the platform routes: `schoolTypeField` (K12, HIGHER_ED, VOCATIONAL), `passwordField` (optional in shape, so a missing one answers as `WRONG_PASSWORD`), `codeField` (valid tenant code: 2 to 40 lowercase letters, digits, hyphens, not a reserved word), `nameField` (NFC, whitespace collapsed, 1 to 100 characters), `emailField` (re-exported from the members module), `changeLimited` (30 changes per 5 minutes per administrator, 429 `RATE_LIMITED`), `noSuchSchool` (404) and `hasPeriods` (409 `HAS_PERIODS`). |
| `service.ts` | `listSchools`, `createSchool`, `reinviteFirstAdministrator`, `setSchoolType`, `setSchoolSuspended`, `listAudit` and their result types. Everything goes through the `platform_*` SECURITY DEFINER functions in a `forUser` transaction; the database re-checks the caller is a platform administrator and writes the platform's audit row. The only school tables touched are the first-administrator `Invitation` and the school's `AuditLog`, in the same transaction as the creation or re-invite. `dbReason` maps the functions' exception names to result reasons; each mutation re-reads the whole school list. |

## API routes: Platform (`/api/v1/platform/`)

Every handler is `withAuth(handler)` plus `platformGuard(auth)`, which reads `User.isPlatformAdmin` and active two-step verification from the database each time (403 `FORBIDDEN`, 403 `MFA_REQUIRED`); none is a school route, so none declares a support area.

| Method | Route | File | Who | Description |
| --- | --- | --- | --- | --- |
| GET | `/api/v1/platform/audit` | `platform/audit/route.ts` | Platform administrator | The platform's own history, newest first (`platform_list_audit`): action, actor, target school id, reason, time. Query `limit` 1 to 200, default 50 (400 `VALIDATION` otherwise). Holds no school data. |
| POST | `/api/v1/platform/schools/[id]/first-admin-invitation` | `platform/schools/[id]/first-admin-invitation/route.ts` | Platform administrator; step-up: own password (403 `WRONG_PASSWORD`, 429 after 5 failures); 30 changes per 5 minutes (429) | Body `{ email, password }` (strict). Sends a school with no active ADMIN a new first-administrator invitation: 409 `HAS_ADMINISTRATOR` when it has one (the database decides), 404 for an implausible or unknown school id. One transaction revokes the school's open ADMIN invitations and writes the new one (7 days), with audit rows in the school's log and the platform's; the email goes out after the response. 201 `{ school, invitation }`. |
| PATCH | `/api/v1/platform/schools/[id]` | `platform/schools/[id]/route.ts` | Platform administrator; step-up: own password; 30 changes per 5 minutes | Body `{ schoolType, password }` (strict). Changes the school type, the only way it changes after creation: 409 `HAS_PERIODS` once the school has any academic period, 404 unknown school. Audited in the platform's log by the database function. Returns `{ school, changed }`. |
| POST | `/api/v1/platform/schools/[id]/suspension` | `platform/schools/[id]/suspension/route.ts` | Platform administrator; step-up: own password; 30 changes per 5 minutes | Body `{ suspended, reason?, password }`. Suspends (a reason of up to 500 characters is required, else 400) or reinstates. Idempotent: a repeat changes nothing and writes no second audit row (`changed: false`). Members of a suspended school get the same refusal as strangers; no membership is touched. Audited in the platform's log. |
| GET, POST | `/api/v1/platform/schools` | `platform/schools/route.ts` | Platform administrator; POST also step-up: own password; 30 changes per 5 minutes | GET lists every school with identity data (id, code, name, type, created, suspended) and four counters (members, administrators, students, campuses); no person or row of any school. POST body `{ code, name, schoolType, adminEmail, password }` (strict) creates the school and its first-ADMIN invitation in one transaction: 409 `CODE_TAKEN`, 201 `{ school, invitation }`, email sent after the response. |
| POST | `/api/v1/platform/support/close` | `platform/support/close/route.ts` | Platform administrator; no password | Ends the support view open on this sign-in (`closeSupport` clears the session's school and records `SUPPORT_CLOSED` while the grant is still live). Safe to repeat. Returns `{ closed: true }`. |
| GET | `/api/v1/platform/support/grants` | `platform/support/grants/route.ts` | Platform administrator | The schools this administrator may open a support view of right now (live grants only): school code and name, the granted areas and when the grant ends. No reason text, no people. |
| POST | `/api/v1/platform/support/open` | `platform/support/open/route.ts` | Platform administrator; step-up: own password; 30 changes per 5 minutes | Body `{ code, password }` (strict). Opens a read-only support view of that school on THIS sign-in, only when a live grant is open to the caller; one 404 `NOT_FOUND` for no such school, no live grant or a suspended school. Replies with the school, the areas and `endsAt` (the earlier of the grant's end and one hour); the school's active administrators are emailed a notice. |
