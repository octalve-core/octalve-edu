# School app — Components

The components behind one school's screens: one folder per area under `src/components/`. The pages in `src/app/(app)/schools/[code]/` stay thin (they verify the school and who is
asking, then render one of these); the screens call the API routes listed in [`../functions/school-app.md`](../functions/school-app.md).

## `src/components/academics/`

The screens of a school's "Academic setup" page (`/schools/[code]/academics`): one panel per section, the dialogs each panel opens, and the small helpers they share. The panels call the APIs from the browser (`getJson`, `sendJson`), except `HigherEdPanel`, which is local-only and mounted nowhere; the page decides which sections a role sees and the APIs enforce the same rules again.

| File | Description |
| --- | --- |
| `AssessmentDialogs.tsx` | Client dialogs `SchemeFormDialog` (modes `create`, `edit`, `version`) and `SchemeArchiveDialog`. The form shows live whether components plus exam equal the total, allows at most 10 components, and in `create` mode loads the first 100 classes for its "Applies to" picker. Calls `/academics/assessment-schemes` (POST, PATCH, `/new-version`, `/archive`); the server judges the scheme. |
| `AssessmentPanel.tsx` | Client component (`schoolCode`, `readOnly`): lists `/academics/assessment-schemes` (In use, Archived or Everything; 20 per page) with each scheme's scope (school default or one class), version and a lock pill. A locked scheme offers "New version", an unlocked one "Edit", both "Archive"; `readOnly` hides every control that writes. A scheme only shows as locked once `lockScheme` has run, which no code in `src` does today. |
| `AttendancePanel.tsx` | Client component (`schoolCode`, `readOnly`): daily roll call. Loads the arms the caller may use (`/academics/attendance/arms`), then the roll of the chosen arm and date (`/academics/arms/[id]/attendance?date=`). Each student gets PRESENT, LATE, ABSENT or EXCUSED and a remark (up to 500 characters); "Mark All Present" keeps EXCUSED; "Save Roll Call" posts every listed student. Dates after today (UTC) are refused, and the screen edits only when the server says `canEdit` (teachers: 7 days back). |
| `ClassDialogs.tsx` | Client dialogs: `ClassGroupDialog` (name, order, an optional stream such as Science or Arts (task 0035), and for a new class the campus it belongs to, fixed afterwards), `ArmDialog` (name, capacity 1 to 1000 or empty), `SubjectDialog` (name, code of 1 to 12 letters or digits), `OfferingsDialog` (tick the subjects a class studies, saved as the full list by PUT; shows only the first 100 subjects) and `ArchiveDialog` (class, arm or subject; says what the server will refuse). Calls `/academics/class-groups`, `/arms` and `/subjects`. |
| `ClassesPanel.tsx` | Client component (`schoolCode`, `campuses`, `readOnly`, `ownCampusId`): the classes with their live arms, and the school's subjects with a name or code search (debounced, 20 per page), with the dialogs above. A campus administrator (`ownCampusId` set) can change only their own campus's classes and arms and cannot change subjects; whole-school classes show "Set by the school". Archived rows are never listed. Calls `/academics/class-groups` and `/academics/subjects`. |
| `GradingDialogs.tsx` | Client dialogs `ScaleFormDialog` (modes `create`, `edit`, `version`; rows of from, up to, letter (max 4) and remark (max 40), at most 12 bands; in `create` mode a button fills a standard A-F scale 70/60/50/45/40/0) and `ScaleActionDialog` (make default, archive). Calls `/academics/grade-scales` (POST, PATCH, `/new-version`, `/make-default`, `/archive`); whether the bands cover 0 to 100 is judged by the server. |
| `GradingPanel.tsx` | Client component (`schoolCode`, `readOnly`): lists `/academics/grade-scales` (In use, Archived or Everything; 20 per page) with a Default pill, a lock pill and the band table, highest band first ("x to under y", top band "to 100"). Offers "New version" (locked) or "Edit" (unlocked), and "Make default" and "Archive" (neither on the default). A scale only shows as locked once `lockScale` has run, which no code in `src` does today. |
| `HigherEdPanel.tsx` | Client component (`schoolCode` is unused; optional `initialDepartments`, `initialCourses`): a demonstration of the credit-unit screens. Shows hard-coded sample departments, courses and three sample registrations kept in local state, with level and semester filters, "+ Register" and editable scores that compute grade, grade point and GPA through `scoreToGradePoint` and `calculateGPA`. It never calls the API, so nothing is saved. Not imported by any page. |
| `model.ts` | Plain module (no `use client`). The types and display rules the panels share: re-exports the view types of `lib/academics` (`SessionView`, `PeriodView`, `ClassGroupView`, `ArmView`, `SubjectView`, `SchemeView`, `ScaleView` and others), `SECTIONS` and `isSection` (the seven section keys), `periodWords` (term, semester or cohort by school type), `formatDate`, `formatRange`, `plusOneYear`, `formatInstant` (the browser's time zone), `parseMark` and `markText`. Also the report shapes for reviewers: `ApiReport` (what `GET .../reports` answers: the question, the masked reporter, the reason, the state, the outcome and the reason given, the assessments it was copied into), `CorrectionSummary` (what a correction counted) and the labels `REPORT_STATUS_LABEL` and `REPORT_OUTCOME_LABEL`. |
| `parts.tsx` | Client building blocks of the panels: `useDialog` (open state; a dialog stays mounted and is re-keyed per opening), `LiveNotice`, `StatusPill`, `ListState` (loading, error with retry, empty), `Pager`, `FormDialog` (pending state, Cancel and Save, and it places `body.<field>` errors from a 400 next to the right field) and `ConfirmDialog` (Cancel focused first). |
| `SectionNav.tsx` | Server-compatible component (no hooks): the tab bar of Academic setup, one link per entry of `SECTIONS` (timetable, attendance, lms, sessions, classes, assessment, grading) as `?section=` addresses, with `aria-current` on the current one. Its comment says "four parts"; there are seven. |
| `SessionDialogs.tsx` | Client dialogs for sessions and terms: `SessionFormDialog`, `ActivateDialog` (the "close the open session first" option asks for the password), `CloseSessionDialog` (24-hour countdown, or 1 minute with the password), `CancelCloseDialog`, `ReopenSessionDialog` (reason of 5 to 300 characters), `ArchiveSessionDialog`, `CopyForwardDialog` (previews with `dryRun`; "Create session" stays disabled until a clash-free preview), `PeriodFormDialog` (end date optional for cohorts) and `ArchivePeriodDialog`. Calls `/academics/sessions/...` and `/academics/periods/...`. |
| `SessionsPanel.tsx` | Client component (`schoolCode`, `campuses`, `schoolType`, `readOnly`, `ownCampusId`): the sessions list (filter by status and campus, 20 per page) with row actions chosen from the session's state (Edit, Open, Close..., Cancel closing, Close sooner..., Reopen..., Copy forward, Archive) and a drill-down `TermsView` for its terms, semesters or cohorts (add, edit, make current, archive). A campus administrator (`ownCampusId`) can act only on their own campus's sessions; whole-school ones show "Set by the school". |
| `TimetablePanel.tsx` | Client component (`schoolCode`, `readOnly`): loads `/timetable` and hands the slots to `TimetableCanvas` (`components/timetable`) with class arm, subject and teacher lists. The class arms are read from `/academics/classes` (no such route; the class list is `/academics/class-groups`, under `classGroups`) and the teachers from the `items` key of `/people/staff` (which answers `staff`), so both lists arrive empty. |
| `useApi.ts` | Client hooks. `useApi(path)` GETs a URL with `getJson` and returns `reply`, `error`, `loading` and `reload(flush)`, which resolves once the new answer is in the DOM; `path = null` loads nothing. `useAfterChange` reloads a list and then puts focus on the summary line if it fell to the body. `failureText` maps 401, 429 and a network failure to fixed messages. |

| `MarksPanel.tsx` | Client component (`schoolCode`, `readOnly`): Marks. The server's own sentence is shown when it refuses. After an import the grid is reloaded from what is saved. |
| `RemarksEditor.tsx` | Client component (`schoolCode`, `card`, `onSaved`): the teacher's and the principal's remark of one card (task 0036), a field only for each remark this person may write now (`card.remarks.canWriteTeacher` / `canWritePrincipal`), a count of 500, Save, a status line; with nothing to write it shows nothing, and once the term's results are published it says the remarks are final. | `model.ts` | Types and pure helpers of the Results screens: `ResultStatus` with `STATUS_LABEL` and `statusTone`, `Options`, `Sheet`, `ReviewItem`, `RosterRow`, `ReportCardData`, `markProblem` (at most two decimals, not above the maximum) and `REGION` / `FIELD` (a `relative` scroll region, see `academics/promotion/model.ts`). |
| `VerifyCredential.tsx` | Client component (`code?`): the public check of a mark or a certificate (tasks 0038 and 0043). Without a code, a form that takes a typed or pasted code (`parseVerifyCode`: the bare code, the whole link, or an old raw `/api/v1/verify…` address) and goes to `/verify/<code>`, refusing anything else in words. With a code, it asks the public API `GET /api/v1/verify/[token]` and, when that is a 404, `GET /api/v1/verify-certificate/[token]`, and shows the first answer found as the heading, sentence and rows of `describe` (`lib/results/verified-view.ts`, pure and unit-tested): a mark, a school's certificate, a certificate of completion, a withdrawn certificate, or a certificate that does not match the school's record; never a score, an admission number or a certificate's metadata. "Nothing found for this code" is a 404 from both routes (or a code that is not 32 hexadecimal characters: no request is made); "The check did not finish" is a 429 or no network on either, and nothing is guessed from it. It replaces the old `VerifyCertificateForm`, which no page ever mounted. |
