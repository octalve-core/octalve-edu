# School app — Components

The components behind one school's screens: one folder per area under `src/components/`. The pages in `src/app/(app)/schools/[code]/` stay thin (they verify the school and who is
asking, then render one of these); the screens call the API routes listed in [`../functions/school-app.md`](../functions/school-app.md).

## `src/components/academics/`

The screens of a school's "Academic setup" page (`/schools/[code]/academics`): one panel per section, the dialogs each panel opens, and the small helpers they share. The panels call the APIs from the browser (`getJson`, `sendJson`), except `HigherEdPanel`, which is local-only and mounted nowhere; the page decides which sections a role sees and the APIs enforce the same rules again.

| File | Description |
| --- | --- |
| `AssessmentDialogs.tsx` | Client dialogs `SchemeFormDialog` (modes `create`, `edit`, `version`) and `SchemeArchiveDialog`. The form shows live whether components plus exam equal the total, allows at most 10 components, and in `create` mode loads the first 100 classes for its "Applies to" picker. Calls `/academics/assessment-schemes` (POST, PATCH, `/new-version`, `/archive`); the server judges the scheme. |
| `AssessmentPanel.tsx` | Client component (`schoolCode`, `readOnly`): lists `/academics/assessment-schemes` (In use, Archived or Everything; 20 per page) with each scheme's scope (school default or one class), version and a lock pill. A locked scheme offers "New version", an unlocked one "Edit", both "Archive"; `readOnly` hides every control that writes. A scheme only shows as locked once `lockScheme` has run, which no code in `src` does today. |
| `AttendancePanel.tsx` | Client component (`schoolCode`, `readOnly`): daily roll call. Loads the arms the caller may use (`/academics/attendance/arms`), then the roll of the chosen arm and date (`/academics/arms/[id]/attendance?date=`). Each student gets PRESENT, LATE, ABSENT or EXCUSED and a remark (up to 500 characters); "Mark All Present" keeps EXCUSED; "Save Roll Call" posts every listed student. Dates after today (UTC) are refused, and the screen edits only when the server says `canEdit` (teachers: 7 days back). |
| `ClassDialogs.tsx` | Client dialogs: `ClassGroupDialog` (name, order, and for a new class the campus it belongs to, fixed afterwards), `ArmDialog` (name, capacity 1 to 1000 or empty), `SubjectDialog` (name, code of 1 to 12 letters or digits), `OfferingsDialog` (tick the subjects a class studies, saved as the full list by PUT; shows only the first 100 subjects) and `ArchiveDialog` (class, arm or subject; says what the server will refuse). Calls `/academics/class-groups`, `/arms` and `/subjects`. |
| `ClassesPanel.tsx` | Client component (`schoolCode`, `campuses`, `readOnly`, `ownCampusId`): the classes with their live arms, and the school's subjects with a name or code search (debounced, 20 per page), with the dialogs above. A campus administrator (`ownCampusId` set) can change only their own campus's classes and arms and cannot change subjects; whole-school classes show "Set by the school". Archived rows are never listed. Calls `/academics/class-groups` and `/academics/subjects`. |
| `GradingDialogs.tsx` | Client dialogs `ScaleFormDialog` (modes `create`, `edit`, `version`; rows of from, up to, letter (max 4) and remark (max 40), at most 12 bands; in `create` mode a button fills a standard A-F scale 70/60/50/45/40/0) and `ScaleActionDialog` (make default, archive). Calls `/academics/grade-scales` (POST, PATCH, `/new-version`, `/make-default`, `/archive`); whether the bands cover 0 to 100 is judged by the server. |
| `GradingPanel.tsx` | Client component (`schoolCode`, `readOnly`): lists `/academics/grade-scales` (In use, Archived or Everything; 20 per page) with a Default pill, a lock pill and the band table, highest band first ("x to under y", top band "to 100"). Offers "New version" (locked) or "Edit" (unlocked), and "Make default" and "Archive" (neither on the default). A scale only shows as locked once `lockScale` has run, which no code in `src` does today. |
| `HigherEdPanel.tsx` | Client component (`schoolCode` is unused; optional `initialDepartments`, `initialCourses`): a demonstration of the credit-unit screens. Shows hard-coded sample departments, courses and three sample registrations kept in local state, with level and semester filters, "+ Register" and editable scores that compute grade, grade point and GPA through `scoreToGradePoint` and `calculateGPA`. It never calls the API, so nothing is saved. Not imported by any page. |
| `model.ts` | Plain module (no `use client`). The types and display rules the panels share: re-exports the view types of `lib/academics` (`SessionView`, `PeriodView`, `ClassGroupView`, `ArmView`, `SubjectView`, `SchemeView`, `ScaleView` and others), `SECTIONS` and `isSection` (the seven section keys), `periodWords` (term, semester or cohort by school type), `formatDate`, `formatRange`, `plusOneYear`, `formatInstant` (the browser's time zone), `parseMark` and `markText`. |
| `parts.tsx` | Client building blocks of the panels: `useDialog` (open state; a dialog stays mounted and is re-keyed per opening), `LiveNotice`, `StatusPill`, `ListState` (loading, error with retry, empty), `Pager`, `FormDialog` (pending state, Cancel and Save, and it places `body.<field>` errors from a 400 next to the right field) and `ConfirmDialog` (Cancel focused first). |
| `SectionNav.tsx` | Server-compatible component (no hooks): the tab bar of Academic setup, one link per entry of `SECTIONS` (timetable, attendance, lms, sessions, classes, assessment, grading) as `?section=` addresses, with `aria-current` on the current one. Its comment says "four parts"; there are seven. |
| `SessionDialogs.tsx` | Client dialogs for sessions and terms: `SessionFormDialog`, `ActivateDialog` (the "close the open session first" option asks for the password), `CloseSessionDialog` (24-hour countdown, or 1 minute with the password), `CancelCloseDialog`, `ReopenSessionDialog` (reason of 5 to 300 characters), `ArchiveSessionDialog`, `CopyForwardDialog` (previews with `dryRun`; "Create session" stays disabled until a clash-free preview), `PeriodFormDialog` (end date optional for cohorts) and `ArchivePeriodDialog`. Calls `/academics/sessions/...` and `/academics/periods/...`. |
| `SessionsPanel.tsx` | Client component (`schoolCode`, `campuses`, `schoolType`, `readOnly`, `ownCampusId`): the sessions list (filter by status and campus, 20 per page) with row actions chosen from the session's state (Edit, Open, Close..., Cancel closing, Close sooner..., Reopen..., Copy forward, Archive) and a drill-down `TermsView` for its terms, semesters or cohorts (add, edit, make current, archive). A campus administrator (`ownCampusId`) can act only on their own campus's sessions; whole-school ones show "Set by the school". |
| `TimetablePanel.tsx` | Client component (`schoolCode`, `readOnly`): loads `/timetable` and hands the slots to `TimetableCanvas` (`components/timetable`) with class arm, subject and teacher lists. The class arms are read from `/academics/classes` (no such route; the class list is `/academics/class-groups`, under `classGroups`) and the teachers from the `items` key of `/people/staff` (which answers `staff`), so both lists arrive empty. |
| `useApi.ts` | Client hooks. `useApi(path)` GETs a URL with `getJson` and returns `reply`, `error`, `loading` and `reload(flush)`, which resolves once the new answer is in the DOM; `path = null` loads nothing. `useAfterChange` reloads a list and then puts focus on the summary line if it fell to the body. `failureText` maps 401, 429 and a network failure to fixed messages. |

## `src/components/results/`

Screens for result entry, approval, report cards and certificates. All five are client components and none is imported by any page or component in `src` (there is no results, report card or certificates page); they are built and not mounted.

| File | Description |
| --- | --- |
| `CertificatesConsole.tsx` | Client component (`schoolCode` is unused; optional `initialCertificates`): a local demonstration of certificate issuing. Shows one sample certificate when none are passed, "issues" a certificate into component state (number from `formatCertificateNumber("OCT", ...)`, hash from `computeCertificateHash` with a placeholder tenant id) and "revokes" it in state; it never calls the certificates API, so its rows have no verification token and no "Verify" link (the public lookup, `/api/v1/verify-certificate/[token]`, takes the token only, not the certificate number). Not mounted on any page. |
| `ReportCardView.tsx` | Client component: a print-friendly report card drawn from props (`institutionName`, `student`, `period`, `summary` with class rank and `PROMOTED` or `REPEATED`, `subjects`, optional `verificationToken` and `verificationHash`). "Print / Save PDF" calls `window.print`; the footer shows the token and `/api/v1/verify/[token]`. Fetches nothing; `student`, `period`, `summary` and `subjects` follow the data of `GET .../people/students/[id]/report-card`, while the school name and one token and hash are passed separately. Uses raw gray and indigo classes and `dark:` variants instead of the theme tokens. |
| `ResultsApprovalConsole.tsx` | Client component (`items`, `onTransition`, `isAdmin`): a table of results with a status filter (SUBMITTED, APPROVED, PUBLISHED, LOCKED), row and select-all checkboxes, and bulk buttons Approve (APPROVED), Publish (PUBLISHED), Reject (DRAFT, with a required reason) and, only when `isAdmin`, Lock (LOCKED). It makes no request: `onTransition(resultIds, toStatus, reason?)` is meant to call `POST .../academics/results/transition`. Uses raw palette classes and `dark:` variants. |
| `ResultsEntryGrid.tsx` | Client component (`periodLabel`, `subjectName`, `students`, `onSaveScores`, optional `onSubmitBatch`, `isLocked`): a mark-entry table with one score per student (0 to 100, steps of 0.5; a cleared box becomes 0; the column says "Score / 100"). "Save Draft" sends every student's score to `onSaveScores`; "Submit for Approval" calls `onSubmitBatch`. It makes no request and ignores each row's `maxScore` and any component scores. |
| `VerifyCertificateForm.tsx` | Client component: a public-style form for a 32-character verification token. Fetches `GET /api/v1/verify/[token]` (the published-result route, not `verify-certificate`) and shows the school, the student's name, session and period, subject and grade, publish date and SHA-256 digest, or the server's message. Despite its name it does not verify vocational certificates. |

## `src/components/people/`

The People page (students and staff lists), the student and staff detail pages, and the dialogs behind them. Every list and change goes through `/api/v1/schools/[code]/people/`, which decides who may do what; these components only show the answer and hide controls when `canEdit` is false.

| File | Description |
| --- | --- |
| `GuardianDialogs.tsx` | Client dialogs for a student's guardians. `AddGuardianDialog` adds a new person (name, phone, email) or an existing guardian found by a search of at least two characters on `GET .../people/guardians?q=`, with a relationship and an optional primary flag. `EditLinkDialog` sends two separate requests, the guardian's name, phone and email first and then the link's relationship and primary flag, so a failure of the second leaves the first saved. `RemoveGuardianDialog` POSTs `.../guardians/[linkId]/remove`, which revokes the link. |
| `model.ts` | Not a component: the types and display rules of the People screens. Re-exports the `lib/people` view types (`StudentView`, `StaffView`, `EnrolmentView`, `GuardianView`, `GuardianLinkView`, `AssignmentView`, `ImportReport`) and `formatDate`, `CampusOption`, `PageMeta`; defines `SECTIONS` and `isSection` (`students`, `staff`), `RELATIONSHIP_OPTIONS`, `CATEGORY_LABEL`, `ENROLMENT_STATUS_LABEL`, `fullName`, `classLabel` and `problemText`. |
| `SectionNav.tsx` | The two links of the People page, `?section=students` and `?section=staff` (props `schoolCode`, `current`), with `aria-current` on the open one, so reload and the back button keep the section. No `"use client"`, so it renders on the server. |
| `StaffDetail.tsx` | Client component (props `schoolCode`, `staffId`, `campuses`, `canEdit`, `fallbackName`): one record from `GET .../people/staff/[id]`, showing kind, campus, phone, email, the sign-in state (`none`, `invited`, `linked`, with notes when access is switched off or the role no longer matches the kind) and the subjects taught. With `canEdit`: Edit, Archive, Restore, Invite to sign in (needs an email), Link and Unlink account, Add a subject and Remove. The record's other fields (date of birth, address, designation, next of kin) are loaded but not shown. |
| `StaffDialogs.tsx` | Client dialogs for staff. `StaffFormDialog` creates or edits (kind teaching or non-teaching, first and last name, phone, email, campus at creation only; the kind is locked while an account is linked) and sends only the fields the API accepts. Also `ArchiveStaffDialog`, `InviteStaffDialog`, `LinkAccountDialog` (choices from `GET .../linkable-accounts`), `UnlinkAccountDialog`, `AssignDialog` (subjects from `/academics/subjects?limit=100`, classes from `useEnrolmentChoices`) and `RemoveAssignmentDialog`. |
| `StaffPanel.tsx` | Client component (props `schoolCode`, `campuses`, `canEdit`) plus `AccountPill`: the staff list from `GET .../people/staff`, 20 per page, with a search that waits 300 ms, a kind filter and a current, archived or everyone filter. Each row links to the detail page and carries a sign-in pill (`No sign-in`, `Invited`, `Can sign in`, `Signed-in access off`); "Add staff member" opens `StaffFormDialog` when `canEdit`. |
| `StudentDetail.tsx` | Client component (props `schoolCode`, `studentId`, `campuses`, `canEdit`, `fallbackName`): the record, the classes (one enrolment per session, newest first) and the guardians, from `GET .../people/students/[id]` and `.../guardians`. With `canEdit`: Edit, Archive, Restore (on `POSSIBLE_DUPLICATE` it asks, then repeats with `allowDuplicate`), Enrol, Move, Withdraw, and add, edit and remove a guardian. Controls show only for a live student; an archived one offers Restore. |
| `StudentDialogs.tsx` | Client dialogs and the `useEnrolmentChoices` hook. `StudentFormDialog` creates or edits (names, date of birth, optional admission number, campus at creation only; on `POSSIBLE_DUPLICATE` it offers "register anyway" and resends with `allowDuplicate`). Also `ArchiveStudentDialog`, `EnrolDialog` (enrol or move), `WithdrawDialog` (reason of at least 5 characters, field limit 300) and `ImportDialog` (CSV up to 1 MB; "Check the file" is a dry run, and the real import is offered only after a clean check). The hook loads up to 100 live sessions and 100 class groups; the current session is the active one, else the first open one. |
| `StudentsPanel.tsx` | Client component (props `schoolCode`, `campuses`, `canEdit`): the register from `GET .../people/students`, 20 per page, with a search on names or admission number (300 ms pause), a class filter for the current session (or "Not in a class yet") and a current, archived or everyone filter. With `canEdit`: Add student, Import and an Export link to `.../students/export` that carries the same filters. Each row links to the detail page. |
