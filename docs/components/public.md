# Sign-in and account — Components

`src/components/auth/` (the forms and panels of sign-in, account recovery, invitations, two-step verification and the account page), `src/components/landing/` (the landing page) and the two forms that sit next to their
page (`/login`, `/setup`).

## `src/components/auth/`

Sign-in step 2, password and email recovery, invitation acceptance, the security cards of the account page, the shared signed-out layout and the small browser helpers they use.

| File | Description |
| --- | --- |
| `AcceptInviteForm.tsx` | Client component: the page an invitation email opens. Reads the token from the URL fragment (`useFragmentToken`), asks `POST /api/v1/invitations/preview` and shows one of: a dead-link message, "sign out first" (signed in as someone else), "sign in to join" (the address has an account, nobody signed in), a Join button (signed in as the invitee) or a name and password form for a new account (`checkName`, `checkNewPassword`). `POST /api/v1/invitations/accept` finishes it: a new account goes on to `/login`, an existing one to `/schools/<code>`. Any failed preview, even a network error or 429, shows as a dead link. |
| `AuthShell.tsx` | Layout shared by every signed-out screen, not a client component itself (the `ThemeToggle` it renders is). From `lg` up a decorative 46% brand panel (`brand.name`, `brand.login` headline, blurb and points) sits beside the form; below that a compact brand header. The logo (the cap icon and the name), in the panel and in the compact header, is a link to `/` (the start page: the landing page for a signed-out visitor, one press from sign-in; a Solo install still being set up goes on to the wizard); the panel is `role="none"` with only its grid, headline and copyright `aria-hidden`, because a link cannot sit inside a hidden region. Props: `children`, `size` (`sm` or `md`, the form column width). Used by the login, forgot-password, reset-password, confirm-email and accept-invite pages and by `SetupWizardForm`. |
| `ChangeEmailPanel.tsx` | Client component: the "Email address" card of `/account`; prop `email`. Views idle, form, sent: the new address plus the CURRENT password go to `POST /api/v1/auth/email-change/request`, and the sent view says the same thing whether or not the address is taken, as the server does. Maps `INVALID_PASSWORD`, `SAME_EMAIL`, `VALIDATION`, 429 and 401 to field or form errors and moves focus to the heading that replaces the control. The link lifetime ("an hour") is hard-coded text. |
| `ChangePasswordForm.tsx` | Client component: the "Password" card of `/account`. Current, new and confirm fields, the new one checked with `checkNewPassword`; posts `{ currentPassword, newPassword }` to `/api/v1/auth/change-password`. `INVALID_CURRENT_PASSWORD` shows on the first field, `VALIDATION` and `SAME_PASSWORD` on the second; success says other devices were signed out (the server keeps this session). |
| `ConfirmEmailForm.tsx` | Client component: the page the confirmation link opens (mailed to the NEW address). Reads the token from the URL fragment and does NOT act on arrival: the single-use token is spent only on a click of "Confirm email address" (`POST /api/v1/auth/email-change/confirm`), so a mail scanner that opens the link cannot consume it. Success says the person is signed out everywhere and links to `/login`; a dead or missing link offers `/account`. |
| `ForgotPasswordForm.tsx` | Client component: step 1 of password recovery. One email field, posts `{ email }` to `/api/v1/auth/forgot-password` and always shows the same "if an account exists, a link was sent" confirmation with the link's 30-minute life (`RESET_LINK_MINUTES`), whether or not the address has an account. 429 and network failures show a form error. Links back to `/login`. |
| `MfaStep.tsx` | Client component: sign-in step 2, shown inside the sign-in card. Props `challenge`, `onBack`, `onExpired(message)`. Takes a 6-digit authenticator code or a recovery code (`SecondFactorField`) and posts `{ challenge, ... }` to `/api/v1/auth/login/mfa`; success goes to `/dashboard`. `INVALID_CHALLENGE` hands back to the password step with a message; 429 pauses the button for 30 seconds (a courtesy, the server enforces); 503 says two-step verification is unavailable. |
| `ProfileDetails.tsx` | Client component: the "Profile" card of `/account`; props `name`, `email`. Edits the display name in place: checks it with `checkName` (the server's rule), sends nothing when the normalised name is unchanged, otherwise PATCHes `/api/v1/account/profile` and calls `router.refresh()` so the header updates. The email is shown read-only; it changes through `ChangeEmailPanel`. |
| `ResetPasswordForm.tsx` | Client component: step 2 of password recovery, the page the emailed link opens. Reads the token from the URL fragment, checks the new password with `checkNewPassword` and posts `{ token, password }` to `/api/v1/auth/reset-password`. `INVALID_TOKEN` shows "This link can't be used" with a link to `/forgot-password`; success says the person is signed out everywhere and goes on to `/login`. |
| `SecondFactorField.tsx` | Client component and helpers shared by `MfaStep` and the "turn off" form of `TwoStepPanel`: `SecondFactorField` (a 6-digit code input or a recovery-code input, by `mode`), `FactorModeToggle`, `factorPayload(mode, raw)` (returns `{ code }` or `{ recoveryCode }`, or null when mistyped, using the same `lib/auth/mfa/codes.ts` rules as the server), `FACTOR_FORMAT_ERROR` and the `FactorMode` type. |
| `SessionRevalidator.tsx` | Client component that renders nothing; `AppShell` mounts it once. It re-runs the server render when the browser restores a page from its back/forward cache (`pageshow` with `persisted`), and when another tab signs out it goes to `/login`, so Back after sign-out does not show a stale signed-in page. The server's own session check stays the authority. |
| `SessionsPanel.tsx` | Client component: the "Active sessions" card of `/account`. Fetches `GET /api/v1/auth/sessions` in the browser (no-store), lists devices with "This device", relative times and "Kept signed in", and offers "Sign out" per other device (`POST .../sessions/revoke`; a 404 is treated as already gone) and "Sign out of all other devices" (`POST .../sessions/revoke-others`). |
| `TwoStepPanel.tsx` | Client component: the "Two-step verification" card of `/account`. Props `available` (false without `MFA_ENCRYPTION_KEY`), `enabled`, `recoveryCodesRemaining`. Views off, password, scan, codes, on, regen, disable call `/api/v1/auth/mfa/enroll`, `/confirm`, `/recovery-codes` and `/disable`. The QR code is drawn in the browser (dynamic `import("qrcode")`); recovery codes are shown once (copy, download as `recovery-codes.txt`, tick "I have saved my recovery codes" to continue); a warning shows at 2 or fewer codes left. Carries its own copy of the `postJson.ts` helpers. |
| `authChannel.ts` | `broadcastSignOut()` and `onSignOutElsewhere(callback)`: cross-tab sign-out over a `BroadcastChannel` named `octalve-auth` (message `{ type: "signed-out" }`); both do nothing where `BroadcastChannel` is missing. `useSignOut` sends, `SessionRevalidator` listens. |
| `postJson.ts` | Browser fetch helpers: `sendJson(path, method, body)` and `getJson(path, signal)` (same-origin credentials) reduce every outcome, a network failure included (`status: 0`, `code: "NETWORK"`), to one `Reply` (`ok`, `status`, `code`, `message`, `data`, `meta`, `details`); `problemFor(reply, field)` reads a `body.<field>` detail; plus the shared messages `NETWORK_ERROR`, `GENERIC_ERROR`, `RATE_LIMITED`, `SESSION_ENDED`. Imported by 38 files (37 under `src/components/` plus `src/lib/offline/indexed-db.ts`), not only by account forms. |
| `useFragmentToken.ts` | Client hook: reads the one-time token from the URL fragment (`#token=...`) of an emailed link and removes it from the address bar with `history.replaceState`, so it stays out of logs, Referer, history and screenshots (a fragment is never sent to a server). Returns `{ token, version }`: `undefined` until read, `""` when the URL had none. It listens for `hashchange`, so a second link opened in the same tab replaces the first; after the first read a reload no longer has the token. Used by the accept-invite, confirm-email and reset-password forms. |
| `useSignOut.ts` | Client hook `useSignOut()` returning `{ signOut, pending, error }`: POSTs `/api/v1/auth/logout`, broadcasts the sign-out to other tabs, then `router.replace("/login")` and a refresh. A failure is reported and leaves the person signed in, so nobody thinks they signed out of a shared computer. Used by the profile menu, the phone nav sheet and the accept-invite "Sign out" button. |

## `src/components/landing/`

The landing page a signed-out visitor sees at `/` (task 0041).

| File | Description |
| --- | --- |
| `LandingPage.tsx` | Server component: the landing page, built from `brand.landing` unless given props (task 0044: `copy`, `name`, `labels`, `lang`, `dir`, `switchTo`, each optional, each default what the page always was; `ENGLISH_LABELS` holds the component's own English words, `LandingCopy` and `LandingLabels` are exported), so a page in another language and from right to left is the same component: `lang` and `dir` go on the outer element only when given, `switchTo` is a quiet header link to the page in the other language (its label in that language, marked with it), and a card needs no icon. With no props, the page is: headline, lead, the things it covers (six in Octalve, each with a decorative icon), the four kinds of people, an OPTIONAL "how it is run" pair that is not drawn when the brand has none, and the closing band). Landmarks `header`, `main` and `footer`; one `h1`, an `h2` per section, an `h3` per item; the header has the product name, `ThemeToggle` and "Sign in"; the links are `/login` (four times: header, hero, closing band, footer) and the brand's `landing.links` (Octalve: "Check a report card", `/verify`; the first is the hero's quiet button and every one is in the footer). No image, script, font or storage of its own; written on the server, so it reads without JavaScript. Rendered by `src/app/page.tsx` for a signed-out visitor. |

## Colocated with the page (`src/app/login/`)

The sign-in form that only the `/login` page uses.

| File | Description |
| --- | --- |
| `LoginForm.tsx` | Client component: the sign-in card. Posts `{ email, password, remember }` to `/api/v1/auth/login`; on `mfaRequired` it swaps in `MfaStep` with the returned challenge (kept in memory only), otherwise goes to `/dashboard`. A 401 shows one message for unknown account and wrong password; a 429 pauses the button for 30 seconds (a courtesy, the server enforces). "Keep me signed in" is unticked by default. It always lands on `/dashboard`: there is no return-to-page. |

## Colocated with the page (`src/app/setup/`)

The first-run wizard form that only the `/setup` page uses.

| File | Description |
| --- | --- |
| `SetupWizardForm.tsx` | Client component with props `requiresToken` and `insecureBaseUrl`: school name, administrator name and email, password twice, and the setup token when `requiresToken`. Posts to `/api/v1/setup` (the token also goes in an `x-setup-token` header); on success it shows "Setup complete" with a button to `/login`. It repeats the password rules inline (8 characters, a letter, a number, 72 bytes) instead of calling `checkNewPassword`, and warns when a production build is not on https. |
