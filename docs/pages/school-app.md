# School app — Pages

The signed-in area: every page under the `(app)` route group of `src/app/` except the platform console. They share one layout (`(app)/layout.tsx`: the session check and the app
shell) and are listed in the order of the navigation (`src/components/shell/nav.ts`). A school's own screens live under `/schools/[code]`: the code in the URL is checked against the
person's membership of that school before anything is read (`src/lib/tenant/page-tenant.ts`), and hiding a menu entry is a courtesy: each page and each API route behind it enforces
its own access. The route has no route-group parentheses.

## The signed-in area

| Route | File | Description |
| --- | --- | --- |
| `layout (app shell)` | `(app)/layout.tsx` | Layout of every signed-in page (`/dashboard`, `/account`, `/platform`, `/schools/...`): calls `requirePageSession()` (no session redirects to `/login`), builds the school list from the person's memberships, adds the school of a live support view as an `ADMIN` entry, and renders `AppShell`. It only displays: a layout is not re-rendered on client navigation, so every page calls its own guard. |
| `/dashboard` | `(app)/dashboard/page.tsx` | Front door after sign-in. One membership redirects straight to `/schools/<code>` (the query string is dropped); several show a picker of school cards (name, role, code); none says to ask a school administrator for an invitation. The list is the person's own active memberships in unsuspended schools. Any signed-in person, platform administrators included (no special case); no session redirects to `/login`. Nav item: `Your schools`. |
| `/account` | `(app)/account/page.tsx` | The signed-in person's own account, outside any school: cards for profile (`ProfileDetails`), email address (`ChangeEmailPanel`), password (`ChangePasswordForm`), two-step verification (`TwoStepPanel`, given `mfaConfigured()` and `getMfaStatus`) and active sessions (`SessionsPanel`). Any signed-in person in any role; no session redirects to `/login` (`requirePageSession`). Not in the navigation: reached from the profile menu and the phone More sheet. |
| `forbidden (403 view)` | `(app)/forbidden.tsx` | The 403 view that `forbidden()` renders inside the shell (from `requireTenantPage` and from pages such as Academics): "You don't have access to this school" and a button to `/dashboard`. It names nothing, so no such school, not a member and a role the page refuses look the same. Needs `experimental.authInterrupts` in `next.config.ts`. |
| `not-found (404 view)` | `(app)/not-found.tsx` | The 404 view for `notFound()` inside the shell (for example a student or staff id that is not in this school): "We couldn't find that page" and a button to `/dashboard`. Hand-written because Next's built-in 404 carries an inline `<style>` the CSP refuses; it names nothing, so "never existed" and "belongs to another school" look the same. |

## One school (`/schools/[code]`)

| Route | File | Description |
| --- | --- | --- |
| `/schools/[code]` | `(app)/schools/[code]/page.tsx` | A school's overview; nav item `Overview`, shown to every role. `requireTenantPage(code, "settings")`: any active member in any role, or a platform administrator whose support grant includes `settings`; others get the 403 view, no session goes to `/login`. Shows the first name, school and role (`ADMIN` adds "all campuses") and the campuses read in `tenant.run` (`ADMIN` all; every other role, `CAMPUS_ADMIN` included, only its own). Renders `AnnouncementsFeed` except in a support view. |
| `/schools/[code]/academics` | `(app)/schools/[code]/academics/page.tsx` | "Academic setup": a tab bar (`SectionNav`, `?section=` timetable (default), attendance, lms, sessions, classes, assessment, grading) over one panel (`TimetablePanel`, `AttendancePanel`, `LmsPanel`, `SessionsPanel`, `ClassesPanel`, `AssessmentPanel`, `GradingPanel`). `requireTenantPage` sends a signed-out visitor to `/login` and a non-member to the 403 view; then only ADMIN, CAMPUS_ADMIN, TEACHING_STAFF and NON_TEACHING_STAFF (the roles that see the `Academics` nav entry) get in, STUDENT and PARENT get `forbidden()`. Panels are read-only except for an ADMIN; a CAMPUS_ADMIN also changes their own campus's sessions and classes, and ADMIN, CAMPUS_ADMIN and TEACHING_STAFF take the roll. A support view (area `attendance` for that section, else `academics`) is always read-only. The API repeats every check. |
| `/schools/[code]/people` | `(app)/schools/[code]/people/page.tsx` | Server page (`force-dynamic`) for the school's students and staff. Not signed in goes to `/login`; `requireTenantPage(code, "people")` (a support view needs the `people` area), then `ADMIN`, `CAMPUS_ADMIN`, `TEACHING_STAFF` and `NON_TEACHING_STAFF` pass and students and parents get the 403 view, matching the nav. `?section=students` (default) or `?section=staff` picks the panel; any other value shows students. Loads every campus of the school, then renders `SectionNav` and `StudentsPanel` or `StaffPanel` with `canEdit` true for `ADMIN` and `CAMPUS_ADMIN` outside a support view. |
| `/schools/[code]/people/staff/[id]` | `(app)/schools/[code]/people/staff/[id]/page.tsx` | One staff record, with the same access as the People page (sign-in, `people` area, the same four roles, the 403 view for others). An id that is not plausible, or a record that is unknown, another school's or outside the caller's campus (`getStaff` applies the caller's campus visibility), is one `notFound()` page. Renders `PageHeader` and `StaffDetail` with the campuses and `canEdit` true for `ADMIN` and `CAMPUS_ADMIN` outside a support view. |
| `/schools/[code]/people/students/[id]` | `(app)/schools/[code]/people/students/[id]/page.tsx` | One student, with the same access as the People page (sign-in, `people` area, the same four roles, the 403 view for others). An id that is not plausible, or a student who is unknown, another school's or outside the caller's campus (`getStudent` applies the caller's campus visibility), is one `notFound()` page. Renders `PageHeader` and `StudentDetail` with the campuses and `canEdit` true for `ADMIN` and `CAMPUS_ADMIN` outside a support view. |
| `/schools/[code]/lms` | `(app)/schools/[code]/lms/page.tsx` | Server page (`force-dynamic`) for assignments, course notes and quizzes. Not signed in goes to `/login`; `requireTenantPage(code, "academics")` needs the `academics` area in a support view. Its role check lists all six roles, so it refuses no member; `canManage` is true for `ADMIN`, `CAMPUS_ADMIN` and `TEACHING_STAFF` outside a support view. Loads non-archived subjects and class groups and renders `PageHeader` and `LmsPanel`. Nothing in the nav links here and the breadcrumb has no label for it; the Academics page shows the same panel but refuses students and parents, who can reach the LMS only here, by typing the address. |
| `/schools/[code]/communication` | `(app)/schools/[code]/communication/page.tsx` | Server page (`force-dynamic`) for the school's messaging. Not signed in goes to `/login`; `requireTenantPage(code)` declares no support area, then only `ADMIN` and `CAMPUS_ADMIN` pass and any other role gets the 403 view (`forbidden()`). A platform administrator's support view is always refused, so the `fieldset disabled` around the panel never applies. Loads the campuses (a campus administrator gets only their own) and every non-archived class arm with its class name, and renders `PageHeader` and `CommunicationPanel`. The nav shows Communication to the same two roles. |
| `/schools/[code]/users` | `(app)/schools/[code]/users/page.tsx` | The school's people and open invitations. `requireTenantPage(code, "people")` resolves the school from the person's own membership (403 view for a stranger, `/login` when signed out); only `ADMIN` and `CAMPUS_ADMIN` pass, everyone else gets the same 403 view, matching the nav (Users for those two roles only). Loads the campuses in `tenant.run` (all for an ADMIN, only their own for a campus administrator) and renders `UsersPanel` with `actorRole`. A support view with the `people` area sees it read-only (disabled `fieldset`). The members and invitations APIs enforce the same rules. |
| `/schools/[code]/question-bank` | `(app)/schools/[code]/question-bank/page.tsx` | The question bank (slice E: Browse, My questions, Review queue; slice B: Reviewers and Settings). `requireTenantPage(code)` for the four staff roles (a pupil or parent gets the 403 view), with NO support area, so a platform administrator's support view gets the 403 view too. Reviewers and Settings are drawn for the school's administrator and a campus administrator only; the Review queue for a reviewer or an administrator. Display only: the APIs decide. |
| `/schools/[code]/settings` | `(app)/schools/[code]/settings/page.tsx` | The school's configuration screen. `requireTenantPage(code, "settings")` resolves the school from the person's own membership (403 view for a stranger or unknown school, `/login` when signed out); the page then gives the same 403 view unless `tenant.role` is `ADMIN`, so campus administrators, staff, students and parents are refused, matching the nav (Settings for `ADMIN` only). A platform administrator in a support view with the `settings` area passes as a virtual ADMIN, read-only: the form sits in a disabled `fieldset`. Renders `SchoolSettingsPanel`, which has three tabs: Configuration, Results approval (sections, which class is in which, and where each approver approves; ADR 0018) and Audit History. The API enforces the same rules. |
| `/schools/[code]/support` | `(app)/schools/[code]/support/page.tsx` | The school's side of audited support access (ADR 0017). `requireTenantPage(code)` is called with no area, so a platform administrator's support view can never open it (403 view); anyone whose role is not `ADMIN` gets the same 403 view, so a campus administrator and every other member are refused. Renders `SupportAccessPanel`. It has no nav entry: it is reached from the "Support access" link on the Settings page (hidden in a support view). The support-grants API enforces the same rules. |
